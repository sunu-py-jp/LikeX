# 自由配置の例（1280×720）

基本の構図には [slide.compose](composition.md) を使う。この資料は、それでは表せない独自の図や細かなレイアウトを低水準コマンドで作るときの参照。指定マスターの領域・背景・書式を優先し、以下の座標や暗色背景を一律に適用しない。要素座標はpx、領域は `x, y, width, height`。ページサイズは1280×720。どの例も最下段に36px以上の余白を残す。

## 1. 主張を中心にした概要

背景 `#111c2e`。左に大きな主張、右に意味のあるシステム概念図。余白を使い、説明文を左右に繰り返さない。

| 要素 | 領域 | 書式・内容 |
| --- | --- | --- |
| 小見出し | 64, 56, 560, 40 | 18px、`#63dbc7`、プロジェクト名 |
| 主張 | 64, 144, 600, 184 | 54px太字、白、2行まで |
| 説明 | 64, 364, 576, 120 | 24px、`#a9b8cb`、3行まで |
| 細いアクセント線 | 64, 528, 112, 3 | `#63dbc7` |
| 対象・提案の注記 | 64, 572, 592, 64 | 18px、`#a9b8cb` |
| 主役の図 | 744, 152, 456, 448 | サービスの細部でなく利用者→中核→価値を示す |

以下は空の資料に1ページを追加する有効なコマンド例。同じページに対する複数のコマンドを1回で渡せる。`concept-cover` 等のIDは既存の資料と重複しないものに変更する。右側は一つの中心的な役割を見せる簡潔な図で、詳細な構成図は別ページに置く。

JSON例は公開モデルAPI・CLIの **nativeコマンド形式**。AIホストの `apply_commands` に渡すwire形式では、公開されたstrict schemaに従い、省略可能な項目を `null` で埋めるなどの変換が必要な場合がある。CLIの例をそのままツール引数へ転記せず、実際のツール定義を優先する。

```json
[
  { "type": "slide.add", "slide": { "id": "concept-cover", "name": "提案の概要", "background": "#111c2e" } },
  { "type": "element.add", "slideId": "concept-cover", "element": { "id": "concept-eyebrow", "type": "text", "text": "CLOUD SYSTEM / PROPOSAL", "x": 64, "y": 56, "width": 600, "height": 40, "fontSize": 18, "color": "#63dbc7" } },
  { "type": "element.add", "slideId": "concept-cover", "element": { "id": "concept-title", "type": "text", "text": "日々の業務を、\n次の成長の基盤に。", "x": 64, "y": 144, "width": 616, "height": 184, "fontSize": 54, "bold": true, "color": "#f7fafc" } },
  { "type": "element.add", "slideId": "concept-cover", "element": { "id": "concept-description", "type": "text", "text": "顧客接点と業務データをつなぎ、\n改善を続けられるクラウド基盤の提案。", "x": 64, "y": 364, "width": 576, "height": 120, "fontSize": 24, "color": "#a9b8cb" } },
  { "type": "element.add", "slideId": "concept-cover", "element": { "id": "concept-platform", "type": "shape", "shape": "rect", "text": "業務とデータをつなぐ\nクラウド基盤", "x": 760, "y": 232, "width": 432, "height": 232, "fontSize": 30, "fill": "#1c344a", "stroke": "#63dbc7", "strokeWidth": 2, "textColor": "#f7fafc" } },
  { "type": "element.add", "slideId": "concept-cover", "element": { "id": "concept-note", "type": "text", "text": "構想案 / 詳細な要件・効果は検証フェーズで確認", "x": 64, "y": 580, "width": 620, "height": 64, "fontSize": 18, "color": "#a9b8cb" } }
]
```

この例の追加だけで完成と扱わず、本文を目的に合わせ、画像プレビューと診断で字幅・収まりを確認する。フォントの自動縮小は前提にしない。

## 2. 顧客への訴求を対比で見せる

背景 `#f5f7fb`。見出しは「待つ業務から、すぐ動ける業務へ。」のように変化を表す。左右の情報量は同じにしなくてよい。数値がない場合、無根拠な「50%削減」等を作らない。

| 要素 | 領域 | 書式・内容 |
| --- | --- | --- |
| 主張 | 64, 56, 1152, 104 | 44px太字、`#142338`、2行にしない |
| 現在の小見出し | 64, 216, 416, 48 | 20px、`#53647a` |
| 現在の課題 | 64, 288, 416, 232 | 26px、3つ以内。大きな箱は不要 |
| 境界線 | 544, 216, 2, 352 | `#d2dce7` |
| 変化の見出し | 608, 216, 592, 56 | 30px太字、`#0b817d` |
| 変化の説明 | 608, 304, 592, 200 | 26px、具体的な使い方を2つ |
| 成功を確かめる指標 | 608, 552, 592, 96 | 18px、測定予定の指標名と検証方法。予測値と実績を区別 |

見出しと短い本文のグループで比較を作り、角丸カード3列に置き換えない。小さな記号を使うなら各グループ1つまでにする。

## 3. 読み順のあるシステム構成図

明るい背景。タイトルは36px、役割見出しは22px、サービス名は18px。主要なデータフローは2〜3px、背景の区画線は1px。サービスを増やして字を小さくするより、主経路と補助経路を分ける。

| 区域 | 領域 | 役割 |
| --- | --- | --- |
| タイトル | 64, 40, 1152, 72 | この構成が何を実現するか |
| 入口 | 64, 168, 192, 160 | 利用者・接点。クラウド境界の外 |
| エッジ・認証 | 304, 168, 200, 160 | 配信やアクセス制御。サービスの役割を明示 |
| 業務処理 | 552, 168, 288, 160 | API・サービス。非公開領域の境界内 |
| データ | 904, 168, 304, 160 | 永続化・検索など。必要なものだけ |
| 非同期の処理列 | 552, 416, 656, 144 | キュー→処理→保存/分析。主経路と別に示す |
| 運用と凡例 | 64, 608, 1152, 64 | 監視・監査の役割、実線/補助線の意味、構想段階の前提 |

主要ノード間に少なくとも48pxの配線用の空間を置く。左右の同じ高さのノードは端点を揃えて接続する。`line.add` は2点で指定するので水平線に人工的な高さを足す必要はない。短い矢印の三角形や線を接続先の文字の上へ重ねない。

ノードの配置が決まったら、`{ "type": "line.add", "slideId": "architecture", "id": "api-data", "start": { "x": 0, "y": 0, "binding": { "targetId": "api", "port": "right" } }, "end": { "x": 0, "y": 0, "binding": { "targetId": "data", "port": "left" } }, "stroke": "#0b817d", "strokeWidth": 2 }` のように接続する。IDは実際の取得結果か同じページで作成した明示IDを使う。ノードの移動・resize・回転には追従するが、第三の箱を自動回避するものではない。右向き矢印線は `endArrow: "triangle"`、左向きは `startArrow: "triangle"`、双方向は両方に設定する。旧 `element.connect` は削除済み。

`line.add` は線を前面に追加する。背面へ置く場合は、明示IDかモデルAPIの `elementIds`（CLIではinspectで取得）を `element.order` に渡し、`direction: "back"` を指定する。背景より下へ隠れないよう重なり順を確認する。

## 4. 期待と次の一歩で閉じる

背景は概要と同じ暗色に戻す。最後は大きな見出しと具体的なアクションを中心にして、構成図の密度から解放する。

| 要素 | 領域 | 書式・内容 |
| --- | --- | --- |
| 小見出し | 64, 64, 1000, 40 | 18px、アクセント。「NEXT STEP」など |
| 未来像 | 64, 172, 1120, 176 | 56px太字、2行まで。顧客が得る状態を書く |
| 次の一歩 | 64, 416, 1000, 104 | 28px、最初に何を一緒に確かめるか |
| 計画の細い線 | 64, 568, 1120, 2 | 補助色 |
| 進め方 | 64, 600, 1120, 60 | 20px。「要件整理 → 小さく検証 → 段階的に展開」のように簡潔に |

約束できない成果や期限を断定しない。4枚を通して文字の役割・色・余白は揃え、構図は変える。生成後は最新の各ページのプレビューを取得し、読みやすさとページ間のリズムを確認する。
